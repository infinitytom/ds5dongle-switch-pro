# NS1 / NS2 主机协议对照与测试说明

更新日期：2026-11-08。r10 已补主机 09 体感编码，功能现状见 [PRO2_FEATURES_CN.md](PRO2_FEATURES_CN.md)；以下 r7/r8 缺口与未完成项保留为历史记录。用户反馈最新版 r7 的任系模式在 NS2 无法识别；本机电脑上的模式切换正常。这里修的是 USB 主机通信路径，不把电脑模拟器或网站识别作为主机验收。

## 兼容目标

| 主机 | 目标模式 | 当前状态 |
|---|---|---|
| NS1 | 纯 Pro（3） | 待本接收器实机验收 |
| NS2 | 纯 Pro（3） | r8 补启动识别与有线报告启动，待主机复测 |
| NS2 | Pro＋麦克风（4） | 共享 Pro 修复；复合设备识别和麦克风输入分别待测 |
| NS2 | Pro2（6） | r8 补原生身份/配对初始化；主机识别与操作仍待测 |

NS1 不以模式 4 / 6 为本轮兼容目标。上述是开发目标，不是已经通过的支持列表。

## 参考项目的筛选

- **主要原生 Pro2 参考：PicoSwitch2 v1.3.0**，提交 `e50f929a27bf822fc46665c92ce54476bff90184`。其 [STATUS.md](https://github.com/notsosaelin/PicoSwitch2/blob/v1.3.0/STATUS.md) 明确记录真实 Switch 2 上的 Pro2/Joy-Con 2 枚举与输入、配对等验证；同时将原生 `0x09` 体感语义列为未解决问题。采用其已验证的 EP0 和 USB 配对流程，不把体感列为已完成。[协议代码](https://github.com/notsosaelin/PicoSwitch2/blob/v1.3.0/src/switch_pro2/switch_pro2.c)。AES 与配对计算模块按 Apache-2.0 引入，许可随分发包提供。
- **一代 Pro 参考：GP2040-CE**。其 [v0.7.12 Release](https://github.com/OpenStickCommunity/GP2040-CE/releases/tag/v0.7.12) 明确列出 Switch 2 兼容的 Switch Pro 输入模式；对照其启动 identify 和有线通信流程。此处不采用通用 HID/HORI 模式替换现有 Pro。[SwitchProDriver](https://github.com/OpenStickCommunity/GP2040-CE/blob/main/src/drivers/switchpro/SwitchProDriver.cpp)。
- **交叉参考：Dycool/NS-PC-Control**，提交 `f0cde8b8d33c86a77863b6fd4d13c36433e14576`。其 [原生主机路径](https://github.com/Dycool/NS-PC-Control/blob/f0cde8b8d33c86a77863b6fd4d13c36433e14576/server/src/switch2_native.cpp) 用于核对 EP0、读存储响应和功能掩码。
- **有限参考：Pico-DualSense-Switch-Bridge**。其 README 记录 Switch 按键和基础震动验证，同时明确体感严重问题；只交叉检查握手，未照搬传感器实现。
- **未作为主机成功依据：switch2-pico**。其 README 明确写尚未完成实机测试，不能因项目名称带 Switch 2 就当作主机兼容证据。
- **既有 SDL / VIIPER 参考**继续用于电脑互操作，不能替代主机初始化证据。

## r7 中的具体缺口与 r8 修改

1. Pro2 没有处理主机开始 Bulk 通信前的 EP0 厂商请求：`C0 03` 读取 64 字节身份、`C0 02` 读取 16 字节信息、`40 04`（捕获的 wValue 为 `0x0276`）完成状态阶段。r8 注册独立厂商回调，不占用 Windows 的 `0x20` WinUSB 描述符请求。身份中的地址使用本板标识，不复制原装手柄地址。
2. Pro2 缺少 `0x15` USB 配对地址交换、密钥交换、AES 挑战和完成回复。r8 引入来源明确的单块 AES 模块，执行真实挑战计算；会话状态仅在 RAM，不声称提供蓝牙直连主机或唤醒。
3. 补充原生初始化所需的固件信息、初始查询、电池/参数查询、`0x0C/06` 功能配置回复和 `0x02/04` 可变长度读取；响应缓存上限 96 字节，USB 分片发送。修正清除功能掩码的行为，以及选择输入报告时启动流。
4. Pro2 描述符增加 HID / Vendor IAD，设备类与 qualifier 同步为复合设备；保留 BL616 不共享双向 FIFO 的端点安排。描述符与原装并非逐字节相同，仍需主机验证。
5. 一代 Pro 增加枚举后的单次 `81 01` 主动识别通知；已有主机查询时不重复通知。主机 `80 04` 在没有显式选择报告时启动完整输入；显式选择 `0x3F/0x30` 后保持选择，`80 05` 不降级报告，保留 r7 龙神修复。模式 3/4 共用此实现。

这些是代码中确实缺失或错误的环节，不等于已经证明是该用户主机不识别的全部原因。仍需在原接收器、线材、底座与主机组合上测试。

## r8 时的未完成项（历史）

- 本项目 r8 尚未刷入或接入真实 NS1 / NS2，不能称为已修复主机兼容。
- Pro2 `0x05` 包含电脑 SDL 路径的传感器数据；主机通常使用的 `0x09` 打包体感未实现。不能据此承诺 NS2 游戏体感。
- Pro2 完整 HD Rumble 2、耳麦音频、NFC 标签服务、原生固件更新、蓝牙直连主机与唤醒仍未实现。
- Pro＋麦克风的 UAC 输入在电脑上有旧版本采集证据；NS2 接受复合设备及游戏语音可用性仍待验收。

## 主机测试顺序

1. 先在电脑刷入本板对应的最新测试固件，用配置页确认固件字符串与当前模式。模式在电脑上选择并保存；USB 身份改变后重新授权。网页更新不会替代固件更新。
2. NS1 只测试纯 Pro。NS2 分别测试纯 Pro、Pro＋麦克风、Pro2；一次只改模式，先使用相同的数据线及直连底座端口。纯 Pro / Pro＋麦克风按主机设置开启 Pro 手柄有线通信。
3. 每种模式分别记录：是否出现手柄、是否能完成 L/R 注册、按键与摇杆、体感、震动、连续游玩、拔插和睡眠后重连。Pro＋麦克风另测输入设备和实际语音。
4. 若不能识别，记录具体模式、配置页 F8 版本、NS2 系统版本、底座/直连连接方式与指示灯表现；下一步需要主机侧 USB 抓包或有线串口日志定位停在哪一步，不能靠电脑测试反推。

## r10：采用更新且有体感实测的参考

原 v1.3.0 尚未解决的主机体感，在 PicoSwitch2 后续提交 `e054bfd1311289f392069ff0d2447e01748c2124` 已有真实 NS2 / 喷射战士3 验证记录。r10 采用其 0x1E（30 字节）DualSense 编码路径，不采用未通过主机测试的试验 0x28 路径。新增 Edge 背键、玩家灯、用户校准分片写入与 NVS 保存；本板仍待真实主机测试。确切来源与限制见 [Pro2 功能清单](PRO2_FEATURES_CN.md)。
