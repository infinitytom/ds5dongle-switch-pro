## 2026-11-08：alpha.10 / r9 Pro 发送堵塞退避与断线历史

用户确认闪烁的是接收器，使用 Pro＋麦克风；充足电后是否仍断线、电量和版本不确定。通过只读 F8/F9/FA 查询当前设备为 r8、模式 4、已断开、电量未知；本次上电输入和发送计数为零，没有发生故障时的会话证据。不能认定低电量或某一固件分支就是本次根因。

代码确认 r8 的 Pro 音频触觉在连续发送失败 50 次后调用整个蓝牙断开；低电量监测本身只改变指示灯，输入失联另外由 3 秒看门狗处理。r9 去掉 Pro 路径的输出失败强制断开，失败后在正常 21.333ms 周期、100ms、250ms、最多 1s 之间退避。失败计数饱和，成功后恢复正常周期；不补发过时触觉。断开后清除退避，避免新连接继承上次故障。DS / Xbox 音频路径保持现有策略。

F9 保留原 53 字节载荷并增加可选尾部（共 63 字节）：标识 D9、HCI 原因、断线前电量/状态、断线计数、当前蓝牙状态、扩展版本 1。强制清理在清空连接对象前记为本机终止，后到的旧连接回调不重复计数。断线前电量在清空实时电量前保存在 RAM，USB 拔插或接收器重启会清空历史。HCI 对端终止不等于已经证明低电量；本机终止也不能单独锁定具体调用路径。

五组 MSVC C11 /W4 /WX 原生测试、七项 Node 页面协议测试及模拟浏览器回归通过。退避测试包含长时间失败、计数饱和、成功恢复；诊断测试覆盖旧载荷、未知电量和不支持的扩展版本，浏览器验证历史原因/60% 电量显示与模式切换。

LCTech BL616 Full-Speed 构建成功：RAM 300576 B（70.73%），nocache 2428 B。固件 `LCT616-DS5 3.18 Pro-dev1 r9`，787136 字节，SHA256 `5166d2726d0d0399be3a880a72b86588673b878f4230faea069d6e65e11bf52b`，日志 `build-tests/firmware-build-r9.log`。本轮未刷入硬件，未验证连续游戏和蓝牙拥塞下真实恢复；软件通过不代表所有掉线解决。

## v0.1.0-alpha.3 USB 故障定位与修复

### 旧固件实机诊断

在用户连接的 LCTech BL616 上确认固件为 `LCT616-DS5 3.18 Pro-dev1`：

- 切到 Pro 后，Windows 出现游戏手柄 TLC 与厂商配置 TLC；厂商接口 F8/F7 可读。
- SDL3 能列出 `Nintendo Switch Pro Controller`，但 `SDL_OpenGamepad` 失败，错误为 `Couldn't setup USB mode`。
- 原始 HID 测试：第一次 `80 01` 收到 `81 01`；第二次 `80 02` 没有回复，后续写入返回失败。
- 查 SDK `drivers/lhal/src/bflb_usb_v2.c`：同编号端点的 IN/OUT 使用相同 FIFO/VDMA 映射；旧版 `0x81/0x01` 会争用 FIFO。
- 诊断完成后已通过配置接口恢复原来的 DS 模式。没有自动刷写设备。

### alpha.3 变化及软件验证

- 改为 HID IN `0x84`、OUT `0x01`；可选麦克风 IN `0x82`，三个端点分别使用不同 FIFO 编号。
- 提供标准 HID 按键、帽开关与四轴的 `0x3F` 报告，默认不依赖 SDL 握手即发送标准输入；主机可切换完整 `0x30`。
- 添加纯 C 描述符测试：纯 Pro/Pro+麦克风、FS/HS、正常/其他速度描述符共八种组合；检查所有端点编号不冲突、接口数量和报告长度。
- 添加 UAC1 麦克风模式 4（2ch/16bit/48kHz、主静音），补上 Pro 音频分支中的蓝牙麦克风启停命令；蓝牙重连保留 USB 主机的麦克风流选择。
- F9 新增带版本标记的运行模式、蓝牙状态、输入快照、USB 收发计数、麦克风解码/峰值和闪存保存结果；保留旧字段兼容。
- 控制台重设计，模拟设备回归覆盖保存确认、自动重连、按键映射、读取失败、Pro+麦克风模式及移动端布局。
- LCTech BL616 Full-Speed 完整编译、链接、镜像后处理成功。
- 固件 778848 字节，SHA256：`b809ff37274118bfcb50c3b66321aa9073ed5af41df41322bd69df72dc0a83b4`。
- RAM 294576 B / 415 KB（69.32%）；本地日志 `build-tests/firmware-build-r3.log`。
